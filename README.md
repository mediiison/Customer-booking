# Запись к мастеру

Онлайн-запись для мастера бьюти-сферы: клиент выбирает услугу, день и время, мастер видит расписание и может отменять записи. Фронтенд на React, бэкенд на Node.js и Express.

![Страница записи](docs/booking.png)

## Что умеет

- Прайс-лист с категориями, длительностью и ценой услуг.
- Свободное время считается на сервере: учитываются часы работы, выходные, уже занятые окна и длительность выбранной услуги. Услуга на 90 минут не встанет в окно на 60.
- Блок «ближайшее свободное время» для выбранной услуги, одним нажатием подставляет дату и время.
- Запись на 21 день вперёд. Сегодняшние слоты закрываются за час до начала.
- Защита от двойной записи: если время заняли, пока клиент заполнял форму, сервер вернёт 409, а форма обновит список слотов.
- Кабинет мастера: записи по дням, сумма за день, отмена записи. Доступ по токену.
- Адаптивная вёрстка, тёмная тема, управление с клавиатуры (выбор услуги, даты и времени сделан на нативных radio-кнопках).

## Стек

| Часть | Технологии |
| --- | --- |
| Клиент | React 18, Vite 5, чистый CSS, шрифты Onest и Unbounded (через `@fontsource`), Vitest |
| Сервер | Node.js 20+, Express 4, встроенный тест-раннер `node:test` |
| Хранение | Память или JSON-файл (без базы данных, чтобы проект запускался одной командой) |

## Быстрый старт

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev
```

Откройте http://localhost:5173. Сервер при запуске печатает токен мастера, он нужен для вкладки «Расписание мастера». Чтобы токен не менялся между запусками, задайте его сами:

```bash
ADMIN_TOKEN=мой-секрет npm run dev
```

Запуск одним процессом, как на сервере:

```bash
npm run build
npm start
```

Express отдаст собранный клиент и API на http://localhost:3001.

### Переменные окружения

| Переменная | По умолчанию | Для чего |
| --- | --- | --- |
| `PORT` | `3001` | Порт сервера |
| `ADMIN_TOKEN` | случайный на каждый запуск | Токен мастера |
| `DATA_FILE` | не задан, записи в памяти | Путь к JSON-файлу, чтобы записи переживали перезапуск |
| `STUDIO_NAME` | `Студия красоты` | Название в шапке |
| `STUDIO_TZ` | `Europe/Moscow` | Часовой пояс студии, по нему считаются «сегодня» и «сейчас» |

Прайс-лист лежит в `server/src/services.js`, часы работы и горизонт записи в `server/src/config.js`.

## API

Ошибки приходят в виде `{ "error": "текст для пользователя", "code": "КОД", "field": "поле" }`.

| Метод и адрес | Доступ | Что делает |
| --- | --- | --- |
| `GET /api/config` | все | Часы работы, горизонт записи, сегодняшняя дата в часовом поясе студии |
| `GET /api/services` | все | Прайс-лист |
| `GET /api/slots?date=ГГГГ-ММ-ДД&serviceId=…` | все | Свободное время начала для услуги в этот день |
| `GET /api/next-free?serviceId=…` | все | Ближайшее свободное окно |
| `POST /api/bookings` | все | Создать запись. `201`, если создана, `409`, если время занято |
| `GET /api/bookings?date=…` | мастер | Записи, с телефонами клиентов |
| `DELETE /api/bookings/:id` | мастер | Отменить запись, `204` |

Доступ мастера: заголовок `Authorization: Bearer <токен>`.

Пример записи:

```bash
curl -X POST http://localhost:3001/api/bookings \
  -H 'Content-Type: application/json' \
  -d '{"serviceId":"haircut","date":"2030-01-15","time":"12:00","clientName":"Мария","phone":"8 926 123-45-67"}'
```

## Устройство проекта

```
server/src/
  schedule.js   чистые функции расписания: слоты, пересечения, ближайшее окно
  validate.js   проверка и нормализация входных данных (телефон приводится к +7XXXXXXXXXX)
  store.js      хранилище записей, память или JSON-файл
  app.js        Express-приложение: маршруты, токен мастера, обработка ошибок
  config.js     настройки и часы работы
client/src/
  components/   страница записи, кабинет мастера, формы
  hooks.js      useApi: загрузка данных без показа ответа от прошлых параметров
  lib/format.js даты, цены, длительности, телефоны
```

Что здесь сделано осознанно:

- **Расписание отделено от Express.** `schedule.js` не знает про HTTP, часы и файлы, поэтому покрыт быстрыми тестами на границы: запись встык, окно короче услуги, последний слот перед закрытием, переход через месяц и год.
- **Время считается в часовом поясе студии,** а не сервера или браузера. Время «сейчас» подставляется в приложение как функция, поэтому в тестах оно фиксированное.
- **Двойная запись исключена.** Проверка свободного слота и добавление записи выполняются синхронно в одном такте, между ними другой запрос не вклинится.
- **Клиенту возвращается минимум.** Ответ на создание записи не содержит телефон, список записей с телефонами доступен только по токену, сравнение токена идёт через `timingSafeEqual`.
- **JSON-файл пишется через временный файл и переименование,** чтобы сбой посреди записи не оставил битый JSON.

## Тесты

```bash
npm test
```

Сервер: расписание, валидация, хранилище и все маршруты API через настоящий HTTP (создание, конфликт, отмена, токен, границы горизонта). Клиент: форматирование дат, цен, длительностей и телефонов.

## Что можно добавить дальше

- База данных (PostgreSQL) вместо JSON-файла.
- Уведомления клиенту и мастеру (Telegram-бот или SMS).
- Перерывы мастера и разные графики по дням.
- Несколько мастеров со своими услугами.
- Ограничение частоты запросов на создание записи.
